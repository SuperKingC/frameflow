# 多动画帧复用方案(idle / 攻击 / 受击 / 移动 / 大招)

目标:同一角色多个动画共用一套图集时,减少图集面积(= 显存 + 包体),不改运行时(SpineCharacterAnimator 依旧只看 meta.animations.loop)。

## 现状与瓶颈(exporter.js)

- `collectEntries()`:所有动画所有帧按**全局联合 bbox** 裁剪,帧帧等大。攻击/大招撑大了 bbox,idle/受击帧跟着带大片透明像素。
- 跨动画**无去重**:减帧(pipeline.js `autoDrop`)只比较单段内相邻帧;不同动画里内容相同的帧各打包一份。
- 好消息:帧换附件(flipbook)架构天然支持共享——skin 附件是全局命名池,**任何动画的 attachment 时间线都可以引用任何附件名**,图集里同一名只占一个 region。复用不需要改格式,只需要改"哪些帧入图集、时间线引用什么名字"。

## L1 跨动画整帧去重(导出期,约 1 天)

对每帧 proc 画布裁到自身内容 bbox 后做哈希,建立全局唯一帧池:

1. 精确层(默认开):单帧内容包围盒 + 像素字节哈希,**位置也须相同**——整帧位移是真实动作,不能合并;哈希碰撞用字节比对兜底。
2. 感知层(可选开关):复用现有 `FS.phashOfCanvas / phashDistance`,距离 ≤ 阈值(默认 8,UI 可调 0–20)且位置差 ≤2px、尺寸差 ≤4px 才合并;不做命中对预览,靠导出统计与 frameMap 排查,介意细微差异就别开。
3. 命名:唯一帧保留首次出现的名字(如 `idle_f00`,序号 padStart 2 位),其他动画时间线直接引用该名;meta.animations[].frameMap 记录逐帧 → 规范附件名映射便于排查。
4. 导出完成提示:状态栏显示「去重 150→112 帧(精确 34,近似 4)」。

收益:AI 同参考图生成的多条视频之间,动作首尾帧、站姿过渡帧重合度高;同一条视频切多段时(见"工作流杠杆")去重最狠。预期 5%~25%。

## L1.5 每帧紧包围盒 + 附件偏移(约 1 天,单项收益最大)

把"全局 bbox 裁剪"改成"每帧内容 bbox 裁剪",位置用附件自身 x/y 表达:

- pipeline.js:从 `computeUnionBBox` 抽出单帧 `contentBBoxOf(canvas)`(逐帧扫描 alpha,可顺带缓存)。
- exporter.js:每帧裁紧包,缩放后 `nextEven`;全局 bbox 只用来定锚点(底部中心)和 skeleton 宽高。
- 附件偏移公式(区域附件 x/y 即四边形中心,Spine y 向上):
  - `att.x = (F.cx − G.cx) × scale`
  - `att.y = (G.bottom − F.cy) × scale`
  - 校验:F=G 时退化为现在的 `x:0, y:H/2` ✓
- skin 每个附件本就有独立 `{x,y,width,height}`,**JSON 格式零改动**;skeleton.width/height 不变,Unity 侧 setup bounds 不受影响。
- 排布:异形帧走现有 shelf 分支(uniform 网格快路径自然失效);后续可换 MaxRects 再压 5~10%。

收益:idle/受击这类近静止动画通常只占画面一角,预期整体图集面积降 40%~70%,通常把超 8192² 的图集拉回 4096² 内。

## L2 部件级复用(实验阶段,"部分帧"的完全体)

flipbook 保持不变,但帧由"整图"变"部件叠加":

1. 部件提取:layer.html 的 SAM2 worker 加 VideoPredictor——每条视频首帧点选部件(头/躯干/双臂/武器),masklet 随视频传播,得到时间上一致的部件掩码。
2. 跨动画部件聚类:按掩码裁剪、质心对齐、归一化 48×48 后 phash 聚类;躯干/头部这类静止部件收敛为 1~2 个变体,武器/挥臂保留各自变体。
3. 导出:骨架改为多 slot(按 z 序),每个 slot 的 skin 附件 = 该部件变体池,变体位置烘进附件 x/y(同 L1.5);动画仍只是 attachment 换名时间线。z 序冲突的帧用 draworder key。
4. 质量:只有聚类距离低于紧阈值才共用变体,否则该帧保留独立整帧兜底;掩码边缘 1px 羽化压接缝。

收益再降 30%~50%,但数据模型从"动画=帧序列"变成"角色=部件池+逐帧摆放",交互(UI 点选、批量传播)和导出器都要动,放最后。

## 工作流杠杆(零代码,决定复用率上限)

- **一条视频多个动作再分段添加**:同源帧风格/光照完全一致,去重命中率最高(现有"添加当前选段"已支持)。
- **提示词约定起手收手**:每条动作视频写"从站姿开始,回到站姿",攻击/受击/大招首尾帧与 idle 互为近重复,还能消掉引擎里动作衔接的跳变。
- 各条视频保持同分辨率同机位,避免缩放/平移差异让哈希失配。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 感知阈值过宽,复用错帧 | 默认只开精确去重;感知合并做成开关+命中预览 |
| 跨视频色彩漂移,共用区域有跳变 | 同视频内合并最安全;跨视频仅精确哈希 |
| 紧包围盒 1px 取整漂移 | 偏移与尺寸统一 nextEven,误差 ≤1px 可接受 |
| 时间线引用规范名,排查困难 | meta.json 记录逐帧 canonical 映射 |
